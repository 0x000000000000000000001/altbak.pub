# Missing C library references

The C reference now covers the 23 library cases in addition to its existing
14 core cases and three historical diagnostics. The Go and JavaScript workloads,
measurements and harnesses are unchanged, as are the 14 existing core C medians.

The new implementation is in [`tmp/c-library`](../../tmp/c-library). Its kernels
are optimized imperative C: pure map/filter/traverse/append operations may fuse
with their only consumer, and local records and references may be scalar-replaced.
Sorting uses a generic natural merge sort which inspects its input, copies it,
recognizes ordered runs and merges them when needed. It does not assume that the
runtime input is descending. All integer arithmetic has defined Int32 wrapping.

Preparation follows each PureScript `prepare`: immutable arrays, strings and
records are created before timing. Per-invocation work, including sorting's
temporary allocation and release, is timed. C strings use sized UTF-16 storage;
code-unit length reads the native length while code-point operations decode the
data. No code-point count or result checksum is precomputed. Fusion preserves
surrogate pairing across concatenated fragments and keeps split fragments separate.

Every timed action passes its input through a non-inlined pointer and memory
compiler barrier. The kernels compile in separate translation units without LTO.
Inspection of optimized assembly confirms an opaque-input call, an indirect
kernel call and an atomic result store in every batch iteration. The expected
answers are used only to validate results. This does not require C to reproduce
the number of opaque calls, closures or allocations in another backend; very
short actions therefore include their respective harness costs.

Validation passes all 23 official oracles, 2,500 array variants, 4,129 record/ref
checks and 5,424 string comparisons with JavaScript per build. Sanitizer builds
also pass, and the original prepared fixtures remain unchanged. These checks
include arbitrary values, signed overflow, Unicode surrogate boundaries, empty
inputs and different rejection positions.

The measurement uses clang 17 `-std=c11 -O3 -Wall -Wextra -Werror`, three global
warm-ups, three local warm-ups, calibrated batches targeting 10 ms, and the
minimum of ten batches per process. Published times are medians of three
independent processes. The host was not isolated. The [JSON archive](2026-11-26-c-library.json)
contains all batch durations, exact medians, source hashes, source snapshots,
assembly and validation logs. The original 493 workload/reference files were
hashed before and after the campaign and remained unchanged.

Reproduce the validation with `node tmp/c-library/test-strings.mjs` and the C
validation commands recorded in `tmp/c-library/measure.py`. The measurement
script refuses to overwrite an existing campaign archive; use new dated paths
for a new measurement.

With the existing Go Release measurements, all four Go/C indicators now cover
37 cases: total ratio **1.21×**, arithmetic mean **9,755.93×**, median **8.44×**,
geometric mean **23.18×**. Previously the same indicators covered only 14 cases
(1.10×, 2.55×, 3.24×, 1.48×). The population changed; these differences are not a
Go performance regression. The largest newly visible gaps are the Effect and
ST reference loops, which clang reduces to calculations on their opaque bounds.
