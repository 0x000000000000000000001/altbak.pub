# State : réduction de la boucle restante — 25 novembre 2026

State passe de **18,144 ns à 13,172 ns**, soit **27,40 % de temps en moins**
et une accélération de **1,38×** dans une campagne avant/après alternée.
Son ratio Go/C passe de **16,21× à 11,77×**.
Les benchmarks, leur harnais, le FFI et la référence C impérative sont inchangés.
L’entrée reste opaque à chaque invocation.

Les [données et preuves](2026-11-25-go-state.json) conservent les échantillons,
sorties brutes, manifestes, changements du compilateur, tests, extraits Go et
contrôles d’opacité.

## Les quatre indicateurs Go/C

Les mêmes quatorze médianes C impératives servent de dénominateurs aux deux
versions Go. Elles viennent de la [campagne avec entrées opaques](2026-11-25-go-c-imperative-opaque.md).
Ni le C ni JavaScript ne sont remesurés ici.

- Ratio des totaux : **1,170834× → 1,117572×**.
- Moyenne arithmétique μ : **6,736814× → 6,399058×**.
- Médiane Q₂ : **7,116203× → 7,187313×**.
- Moyenne géométrique G : **2,849976× → 2,783742×**.

Le total Go est de **10,255203 ms avant** et
**9,788691 ms après**, pour **8,758890 ms en C**.
Les calculs utilisent les temps avant arrondi : ΣGo/ΣC pour le ratio total,
puis la moyenne, la médiane et la moyenne géométrique des quatorze ratios.
Les 23 cas Incl WIP ne participent pas à ces indicateurs.

La [publication précédente](2026-11-25-go-church.md) donnait respectivement
**1,093780×**, **6,616414×**, **7,011738×** et **2,806044×**,
avec State à **17,817 ns**. Les gains annoncés ici utilisent la nouvelle paire
avant/après, qui réexécute aussi les anciens binaires.

State économise seulement **4,972 ns** sur environ 9,8 ms. La baisse de 4,55 %
du total ne peut donc pas lui être attribuée : elle provient surtout des
variations de Red-Black Tree. Les plages des totaux par processus se recouvrent :
**9,705–10,450 ms avant** et **9,610–9,938 ms après**. Q₂ augmente légèrement
(+1,00 %) dans cette campagne ; améliorer State seul ne garantit pas la baisse
de chacun des quatre indicateurs. L’objectif de 1× n’est pas encore atteint.

## Transformation du compilateur

L’évaluation scalaire fermée réduisait déjà les soixante modifications de State
à un incrément de 60. Une lecture stricte inutilisée de `Data.Unit.unit`,
conservée à l’intérieur de cet incrément, empêchait toutefois la reconnaissance
de la récurrence. Il restait une boucle de vingt passages pour l’entrée usuelle.

`AffineLoops` reconnaît désormais les lectures de bindings globaux inutilisés
avant l’appel récursif ou dans l’opérande constant de l’addition. Leur première
évaluation reste conservée, dans l’ordre, sous la garde positive. La règle est
limitée à 64 lectures et refuse les appels, projections, lectures locales et
bindings encore utilisés. Les getters PureScript mémorisent leur initialisation ;
les getters étrangers renvoient un binding matérialisé à l’initialisation du
package. Lire une valeur fonctionnelle ou un `Effect` ne l’exécute pas.

Pour un compteur positif dans Int32 et un accumulateur déjà normalisé, le code
calcule `seed + count * increment`, puis normalise le résultat en Int32. Le
produit et la somme tiennent dans `int64` aux bornes admises. La boucle d’origine
reste le chemin de repli pour zéro, les valeurs négatives ou les entrées larges.
Le contexte de traduction de chaque lecture conserve sa représentation propre.
La règle s’applique aussi aux workers locaux ; elle ne dépend d’aucun nom ni
résultat de benchmark.

Dans l’assemblage final, l’appel à `opaqueValue` via le worker FFI est conservé,
et sa valeur retournée alimente le calcul de State. Le chemin positif effectue
`60*n + seed`, normalise et retourne, sans boucle. Le compilateur Go élimine la
lecture triviale de Unit, déjà initialisé. Les appels et conversions autour du
calcul restent une piste pour réduire l’écart résiduel ; leur coût individuel
n’est pas quantifié ici.

## Validation et autres cas

- **42 tests ciblés** passent : arithmétique Int32, entrées larges, cas zéro,
  lectures imbriquées, ordre d’évaluation et arrêt après une erreur, refus des
  effets inconnus et des bindings utilisés, budget partagé de lectures.
- Une fixture source indépendante concorde avec son oracle JavaScript pour les
  hôtes JS et natif, en Release et Dev. Des assertions sur le Go généré prouvent
  l’activation de la garde pour trois formes : worker global, worker local et
  lecture d’une fonction étrangère sans l’appeler.
- **88 variantes d’entrée** concordent avant/après et avec le C inchangé.
  Les sondes substituent seulement le retour de la frontière opaque et
  vérifient exactement un passage par cette frontière par action.
- Les **306 résultats** des douze processus et leurs lots calibrés sont validés.
  Les empreintes des benchmarks, du harnais, des références et des exécutables
  sont contrôlées avant et après les mesures.
- Les **16 tests** du calcul des ratios et de leur précision passent.

La comparaison des **610 sections Go App14** et **657 sections AppAll37**
trouve une seule section modifiée dans chaque build : State spécialisé.
Les autres sections, imports, fichiers et le runtime sont identiques.

Les trois processus App14 donnent **17,709–18,743 ns avant** et
**13,171–13,562 ns après** pour State. AppAll37 confirme le gain :
**18,215 → 13,094 ns**, soit **1,39×**. Ces plages sont les valeurs observées,
pas des intervalles de confiance.

Deux cas dépassent +5 % dans les paires principales :

- AST App14 : **38,265 → 40,318 ns** (+5,37 %), avec des plages recouvrantes de
  **37,629–38,451 ns** et **37,723–42,359 ns**.
- `st/ref-write-10000` AppAll : **6,164266 → 7,100281 µs** (+15,18 %), avec des
  plages recouvrantes de **6,111511–7,151062 µs** et **6,025655–7,227661 µs**.

Une contre-mesure isolée reprend les mêmes getters compilés et le même harnais,
avec trois processus par variante et par cas. Les douze résultats attendus
sont validés. ST donne **6,924500 → 6,304545 µs** (−8,95 %) : la hausse initiale
n’est pas reproduite.

AST donne **36,032 → 37,538 ns** (+4,18 %). Ses plages isolées,
**35,933–36,115 ns** et **37,500–38,187 ns**, ne se recouvrent pas.
Un léger ralentissement reste donc observé. Le code de son action, de son
harnais et du runtime est identique ; sa cause n’est pas établie. Cette limite
est conservée dans le bilan. Aucun échantillon ni agrégat principal n’est
remplacé par ces diagnostics.

## Protocole et reproduction

Apple M4 Pro, 48 Gio, Go 1.27.0, darwin/arm64, Release, GOGC=800, sans PGO,
GOMAXPROCS par défaut. Chaque paire utilise trois processus par variante,
en ordre AB/BA/AB. Le harnais conserve ses échauffements, sa calibration et
le minimum de dix batches ; la valeur publiée est la médiane des trois minima
de processus. Les builds et tests du compilateur étaient terminés avant la
campagne. La machine n’était pas isolée des autres activités utilisateur.

Le bootstrap natif réussit avec le seul avertissement `ShadowedName` préexistant
dans `PrivateSTRegions.purs:266`. Le contrôle documentaire valide 44 documents
et 133 entrées du module-map.

L’entrée App à 14 cas fournit les chiffres Stable. La paire AppAll à 37 cas
contrôle les régressions et fournit les 23 chiffres Incl WIP. Le README
actualise uniquement la colonne Go Release dans ses tableaux existants.
Les autres colonnes et les références gardent leurs mesures.

Le script de collecte est inclus dans l’archive. Son rejeu intégral vérifie
aussi le catalogue antérieur à cette publication. Pour réexécuter directement
les deux paires de binaires figés dans de nouveaux répertoires :

```sh
env -u GOMAXPROCS -u PPROF GOGC=800 python3 -B bin/benchmark/measure.py \
  --plan var/benchmark/go-state-20261125/campaign/core-plan.json \
  --output var/benchmark/go-state-20261125/replay-core

env -u GOMAXPROCS -u PPROF GOGC=800 python3 -B bin/benchmark/js-ratios.py \
  --before var/benchmark/go-church-20261125/after-all \
  --after var/benchmark/go-state-20261125/after-all \
  --output var/benchmark/go-state-20261125/replay-all
```

Les quatre indicateurs se recalculent avec les temps C conservés dans
`campaign.frozen_reference.c_times_us` de l’archive. Les tentatives intermédiaires
sont identifiées séparément et ne participent pas aux mesures finales.
