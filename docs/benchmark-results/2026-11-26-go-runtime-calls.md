## Probe and selected change

The preceding corrected CPU profiles exposed boxing and call overhead after compact record projections were improved. This campaign uses those profiles to select a small runtime probe; it does not claim a new post-change CPU profile. The probe imports the three actual prepared record actions from the frozen before-all bundle. Go overlays select diagnostic runtime variants without changing the official generated package, benchmarks, C reference or opaque barriers. Each binary checks the three expected results 1006, 1072 and 1272 before measurement; these are three distinct expected cases, not a varied-input correctness corpus.

The selected variant separates Box's Value identity case from its large type switch. The wrapper becomes inlinable (reported cost 74 against budget 80 for the interface shape). A combined Apply fast path remains non-inlinable and worsens metadata-bearing calls from 2.829 to 3.407 ns in the probe; it is rejected. **Apply is unchanged.** All variants, both probe series and compiler inlining diagnostics remain available under probe-runtime.

The expanded 150 ms probe measures small 10.462 → 8.155 ns, medium 19.443 → 18.922 ns and large 36.643 → 35.559 ns. Box of native Value changes 1.651 → 0.744 ns; Box of any containing Value changes 1.705 → 1.065 ns. Expanded scalar/string/array/function cases show no new allocations. The int case rises 6.132 → 6.246 ns in this short probe; it is retained. These diagnostic timings are not substituted for the official results below. In particular, the official small-record gain is smaller than the probe's gain.

In runtime/runtime.go, Box[T] now performs its original identity assertion any(val).(Value) in a small wrapper and returns the existing Value unchanged. All other original switch branches move into private boxSlow(any). An independent structural check restores the original Box preamble and reproduces the entire previous runtime byte-for-byte. Tags, integers, pointers and function metadata remain intact; other scalar, foreign, nil, recursive-array and function cases retain the original behavior. Callback execution stays deferred and arrays retain their alias behavior. No input, opaque effect or computed result is cached.

The source delta is exactly runtime/runtime.go and the new runtime/box_fast_path_test.go. Source.purs is unchanged. Its three generated Source.js/go/rs embeddings are regenerated by the normal build, checked against the canonical runtime, and captured separately before/after. No PureScript code-generation transformation, benchmark name, workload constant, benchmark/library FFI change or C change is introduced.

## Build and runtime-only generated scope

The full runtime Go test suite passes without a name filter in both optimized and race builds. The Node harness reports three passing entries: one parent and its two build subtests; this is not a count of three Go tests. The five new targeted Box tests, including 22 function subcases, are contained in that full suite and are not recounted as separate Node tests. They exercise identity/metadata, scalar edges, Unicode and invalid bytes, named and typed-nil values, recursive arrays/aliases, deferred callbacks across GC and deferred failure of nil functions.

The first native bootstrap verifies 558 TAST modules / 346,791 types, with a 42.8 s frontend. It reaches all emitted modules, FFI validation and entry points, then fails during atomic cache publication with ENOSPC. No production Go output or replacement native compiler is published by that failed attempt. The original full and stage logs are retained. The root agent clears only Go's regenerable build cache, restoring approximately 27 GiB free; sources, archives, module downloads and frozen executables are preserved.

The recovery revalidates and reuses the same TAST workspace, then reruns Go generation (196.1 s) and Go compilation (44.4 s), followed by atomic binary installation. It does not rerun the frontend or change source to recover. The recovery script, exact commands, source checks and output hash are archived. All 202 final source hashes remain fixed, and 205 source/binary hashes identify the compiler used for measurement. The pre-existing PrivateSTRegions shadowing warning retains unchanged source provenance. Future bootstrap attempts check for at least 8 GiB free.

Both benchmark builds contain exactly the same emitted modules as before: 633 core and 683 AppAll sections, all byte-identical. Headers, initialization, FFI and generated measurement harness are also identical. The only changed generated file is gopurs_runtime/runtime.go, which matches the canonical before/after runtime exactly. Since every binary links this runtime, identical emitted actions may still be affected; the scope is not restricted to the three record actions. Opaque call sites and their noinline barrier remain unchanged.

## Protocol, remaining validation and publication

Three independent processes per build in AB/BA/AB order for each suite; three global and three local warm-ups, batches calibrated to at least 10 ms and the minimum of ten batches per process. Each published time is the median of three process minima. Release Go, GOGC=800, default GOMAXPROCS, no PGO. All compilation, tests and profiling stop before timing. The host is not isolated. C and JS are not remeasured. All 306 expected outputs and source/binary guards pass. Independent recalculation reproduces the four indicators from the retained samples. No primary or secondary increase exceeds 5%, so no extra regression timing campaign is run.

Six distinct native-effect-callback Node unit tests pass. The immediate-FFI argument source fixture passes 14 observations per execution on JS-host and native-host compilers, each in Release and Dev. Its actual JavaScript oracle and both Go profiles agree byte-for-byte; it covers argument/factory/thunk/continuation order, saved/replayed actions and changing arguments. These fixtures are separate from the full runtime suite. The previous record projection/alias corpora are not rerun or counted as new evidence for this campaign.

The archive contains the baseline and plan provenance, runtime source/test delta, generated embeddings, probes, rejected Apply trial, failed/recovered bootstrap logs, raw measurements and independent validation. Only existing Go Release README cells are updated, without adding tables or changing references/statuses. The removed ratio catalogue remains absent.
