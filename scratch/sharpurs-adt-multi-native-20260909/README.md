# Sharpurs — integrated native ADT functions with several arguments

This audit measures actual compiler generation in the full Release application. Before is the last normal generation with native Int arithmetic. After is regenerated by Sharpurs with the ADT integration; no generated F# was manually patched. The normal Release application is rebuilt from exactly the same 355 source inputs as measured after.

## Results

Five fresh processes per version, sequential order **ABBAABBAAB**. Each process runs the unchanged `App.main` and its 14 official tests; each reported test time is the benchmark's existing best of 10. Statistics below are medians of the five process results, in milliseconds.

| Metric | Before median | After median | Change | Before range | After range |
| --- | ---: | ---: | ---: | --- | --- |
| Total | 138.49000 | 88.88000 | -35.82% | 135.62000–143.44000 | 88.29000–90.61000 |
| RBTree | 89.92867 | 39.81800 | -55.72% | 87.08663–94.84054 | 39.24471–42.31350 |
| Lazy | 36.16317 | 34.86854 | -3.58% | 35.70525–36.24613 | 34.00500–34.98992 |

Lazy source is byte-identical before/after; its small measured difference is contextual variation and cannot be credited to a Lazy optimization.

All **140 outputs**, names and test orders match the historical reference. Source, build and runtime hashes remain unchanged throughout measurement. Per-test medians need not sum to the total median. These are descriptive local CPU measurements; no RAM, allocation or GC measurement was performed.

The official main `altbak.pub/README.md`, frozen as [README.baseline.md](README.baseline.md), reports historically **185.39 ms total**, **100.07783 ms RBTree** and **71.20333 ms Lazy**. Its final native optimized column gives **65.156 ms RBTree** and **0.075 ms Lazy**. These historical numbers are contextual references, not simultaneous controls. Native RBTree uses mutable `SortedSet`, ascending insertion and returns Count 100000; compiled RBTree keeps its persistent Okasaki tree, descending insertion and returns depth 22. Native Lazy uses 1000 increments and returns 1000; the compiled workload creates/forces one million thunks and returns 1000000.

## What actually changed

Normal generation changes **1 F# source file** and leaves **354 other build inputs** byte-identical. The declaration inventory finds **4 newly generated native functions**. Full source diffs and copies are retained beside [generation-inventory.json](generation-inventory.json).

- `Test.RBTree.fs`: `Test_RBTree_balance_adt_native`, `Test_RBTree_buildTree_adt_native`, `Test_RBTree_ins_adt_native`, `Test_RBTree_insert_adt_native`.

This is general compiler output selected from typed PBO information. The measured gain covers balance, ins, insert and buildTree together; it is not an attribution to ins/balance alone. The final conservative source filter rejects every qualified reference from another module except an exact allowlist of primitive Int/Bool methods and dictionaries plus Data.Boolean.otherwise. Imported constructors and native helpers have no exemption; local dependent functions also remain generic when a dependency is rejected. Only constructors and native functions from the current module are available after their emission. Uncertain typing, nonexact source arity, and direct/inlined/imported partial dependencies keep the generic route. The before sources match the previous isolated RBTree audit's before manifest exactly. A final eligibility-only compiler change was rebuilt and regenerated after the first capture; all 355 generated inputs remained byte-identical, so the existing Release builds and DLL validations stayed valid. The initial manifest/bundle are archived separately and inputs.json records the final compiler provenance. Source/bundle capture provenance is recorded in [inputs.json](inputs.json): working compiler sources were first captured during concurrent development, so that initial source snapshot is not asserted to reconstruct the frozen before bundle. Frozen generated files and copied bundles carry separate hashes.

## Validation

The scripts load the actual built Release DLLs in separate optimized FSI processes. The before DLL writes an oracle with **1067 exact structural/result observations**; after checks every encoded constructor, color and integer value, including the full tree of 100000 ascending values produced by descending insertion, with depth 22.

| Validation | Before assertions | After assertions |
| --- | ---: | ---: |
| Insertion | 522281 | 525552 |
| Tree / depth / makeBlack | 27087 | 27087 |
| Balance | 138 | 137 |
| Lazy | 333 | 333 |
| CodePoints | 165 | 165 |

Coverage includes the four balance rotations and default case, red/black and BST invariants, persistence and shared untouched branches, duplicates and Int32 limits, public/recursive/native entry points, reused partial applications, argument evaluation order and exception identity/chains. Total functions over valid typed ADTs have no arbitrary user callback inside their bodies; exception checks cover supplied argument evaluation and the unchanged public exception boundaries. Ill-typed FFI payloads and null unions are printed separately as diagnostics and are not treated as the PureScript language contract. The compiler fixture in [adt-multi-validation/validation.log](adt-multi-validation/validation.log) also passes **301 F# assertions and 93 JavaScript assertions** (59 selection/generation/fallback checks, plus 34 checks on 17 generic FSI warnings FS0025/FS0040). It verifies direct/inlined/imported unsafePartial and transitive fallback, captured/reused applications, and injected short-circuit/argument exceptions. No warning comes from a native function definition or the PureScript fixture.

The test sources, logs and oracle are hashed in [validation-files.json](validation-files.json). No validation process runs concurrently with the timing series.
